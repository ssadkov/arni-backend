# Бонус $15 на DeepSeek для платных аккаунтов — спецификация

> **Статус: черновик для обсуждения.** Ничего здесь не утверждено. Суммы, сроки, лимиты и сама схема с отдельным кошельком могут измениться после обсуждения 2026-11-21. Не реализовывать, пока документ не будет подтверждён.

Черновик от 2026-11-20.

## Цель

С 2026-11-20 платные аккаунты видят DeepSeek V4.1 Flash 1017 и платят за него из своего бюджета (PR «DeepSeek for paying accounts»). Теперь нужно:

- выдать каждому платному аккаунту **$15 бонуса, который тратится только на DeepSeek**;
- бонус действует **до 2026-12-31 23:59:59 по Алматы** (UTC+5), то есть до **2026-12-31T18:59:59Z**;
- после этого бонус сгорает. Основной баланс остаётся нетронутым.

Бонус служит мостом к тарифу на DeepSeek. Розничную цену тарифа на январь эта спецификация не задаёт: см. «Открытые вопросы».

## Кому

**Платный аккаунт** — это пользователь, у которого есть `AccountBudget` с `enabled = true` и `validUntil` позже момента начисления. На 2026-11-18 таких было **19**. Флаг legacy `PRO` не используется: на 2026-11-18 его не было ни у одного активного аккаунта.

Новый платный аккаунт, появившийся до 2026-12-31, получает бонус при первом начислении основного бюджета.

## Почему не хватает текущей схемы

У `AccountBudget` один баланс и один `validUntil` на весь аккаунт, а модели не различаются. Если просто начислить $15 через админку:

- бонус можно будет потратить на Claude через Bedrock;
- `validUntil` всего аккаунта сдвинется на дату начисления плюс `days`;
- бонус смешается с оплаченным балансом, и сжечь его 31 декабря будет нельзя.

Поэтому нужен отдельный **бонусный кошелёк с ограничением по модели и своим сроком**.

## Модель данных

Новая таблица `BudgetWallet`:

| Поле | Тип | Смысл |
|---|---|---|
| `id` | uuid | |
| `userId` | → `AccountBudget.userId` | |
| `kind` | string | `deepseek_bonus_2026` |
| `models` | string[] | Модели, на которые можно тратить: `['deepseek/deepseek-v4.1-flash-1017']` |
| `balanceMicros` | int | Остаток в микродолларах |
| `grantedMicros` | int | Сколько начислено, для отчёта |
| `weeklyLimitMicros` | int | Собственный недельный лимит кошелька |
| `weeklyUsedMicros`, `weeklyStartedAt` | int, datetime | Окно, как в `AccountBudget` |
| `expiresAt` | datetime | `2026-12-31T18:59:59Z` |
| `createdAt` | datetime | |

Уникальный ключ — `(userId, kind)`: один бонус на аккаунт.

В `BudgetReservation` добавить `walletId` (nullable) и `walletMicros`: сколько из резерва взято из кошелька. Это нужно, чтобы возврат при закрытии резерва ушёл в тот же источник.

В `BudgetEntry` новых полей не нужно. Начисление записывается как `kind: 'grant'` с ключом `wallet:<kind>:<userId>`, списания как `reserve` и `refund` с пометкой кошелька в `note`.

## Порядок списания

Для запроса к модели из `wallet.models`:

1. Проверить, что кошелёк не истёк (`now < expiresAt`), в нём есть остаток и не превышен его недельный лимит.
2. Резерв берётся **сначала из кошелька**, а если его не хватает, недостающая часть берётся из основного баланса. Если бонус кончился, DeepSeek продолжает работать за основной баланс, как сегодня.
3. Окна аккаунта (`fiveHour*`, `weekly*`) учитывают **весь** расход, включая бонусный. Так один и тот же человек не может обойти свои лимиты через бонус.
4. При закрытии резерва фактическая стоимость (`usage.cost` от OpenRouter) списывается в той же пропорции. Разница возвращается в кошелёк, если `now < expiresAt`. Если кошелёк уже истёк, разница сгорает и в основной баланс не переносится.

Для любой другой модели кошелёк не используется.

Резерв, открытый до `expiresAt` и закрытый после, закрывается по обычным правилам: бонус к этому моменту уже зарезервирован.

## Лимиты

| Параметр | Значение | Почему |
|---|---:|---|
| Бонус | **$15** | Решение от 2026-11-20 |
| Недельный лимит кошелька | **$3** | 6 недель до конца года × $2,5 плюс запас. Не даёт сжечь бонус за несколько дней. |
| Лимиты аккаунта за 5 часов и неделю | без изменений | Сейчас по умолчанию $2 / 150 шагов и $5 / 1000 шагов |
| Ответ модели | 64K токенов | Уже действует для DeepSeek (PR #45, #46) |

**Ожидаемый расход.** Тест 2026-11-19 показал **$0,00064 за шаг** при кэше 88% и коротком контексте. На реальном контексте бесплатного тарифа (~95K входа на шаг) ожидается **~$0,002 за шаг**, тогда $15 хватит примерно на 7 500 шагов. Медианный пользователь бесплатного тарифа делал ~116 шагов за 14 дней, поэтому большинство потратит **$1–3 из $15**.

Худший случай: все 19 платных аккаунтов тратят бонус полностью, это **$285**. Ожидаемый расход до конца года — **$20–60**. Это оценка, а не замер.

## Деньги на стороне OpenRouter

- Отдельный ключ `OPENROUTER_PAID_API_KEY` с лимитом расхода **$100** до конца года. Без него DeepSeek для платных аккаунтов работает на основном ключе (так сделано в PR от 2026-11-20).
- Пополнить баланс OpenRouter до выкатки. Бесплатные модели и DeepSeek используют один баланс аккаунта OpenRouter. Нужно проверить, что трата баланса не понижает дневной лимит бесплатных моделей.

## Что видит пользователь

Клиенты: Arni Code и Arni Lite.

- В строке баланса отдельная строка: **«DeepSeek бонус: $12,40 из $15 · до 31.12»**.
- В списке моделей у DeepSeek метка **«Бонус»**, пока в кошельке есть остаток.
- Когда бонус кончился или истёк, метка исчезает. DeepSeek остаётся доступен за основной баланс.
- Достигнут недельный лимит кошелька: запрос идёт за основной баланс, без ошибки. В строке баланса появляется подсказка «бонус на неделю исчерпан, обновится <дата>».

`/api/models` и `/api/budget` (или эндпоинт, который отдаёт `budgetSnapshot`) возвращают кошелёк отдельным полем:

```json
"wallets": [{ "kind": "deepseek_bonus_2026", "models": ["deepseek/deepseek-v4.1-flash-1017"],
  "balanceMicros": 12400000, "grantedMicros": 15000000, "expiresAt": "2026-12-31T18:59:59Z",
  "weekly": { "usedMicros": 800000, "limitMicros": 3000000, "resetsAt": "..." } }]
```

Старые клиенты это поле игнорируют. Списание всё равно идёт правильно, потому что логика целиком на сервере.

## Админка

- Карточка пользователя: блок «Бонусный кошелёк» с остатком, сроком, недельным окном и последними списаниями.
- Кнопка **«Начислить бонус DeepSeek всем платным»**. Идемпотентна: повторное нажатие не начисляет дважды благодаря ключу `wallet:deepseek_bonus_2026:<userId>`. Перед начислением показывает, сколько аккаунтов получат бонус.
- Отчёт: суммарно начислено, потрачено, осталось, число аккаунтов с ненулевым расходом.

## Выкатка

1. Миграция Prisma: `BudgetWallet` и поля в `BudgetReservation`. Проверить, что миграция применилась в production **до** деплоя кода: 2026-11-19 запись в `ModelRequest` падала из-за колонки `client`, которой не было в базе.
2. Деплой сервера с порядком списания и отдачей кошелька в API.
3. Начислить бонус через админку и проверить на одном внутреннем аккаунте: запрос к DeepSeek, затем к Claude, затем истечение (тестовый кошелёк с `expiresAt` через минуту).
4. Разослать платным пользователям сообщение о бонусе.
5. Выпустить клиенты с отображением кошелька. Можно позже: списание работает и без них.

## Проверки

- Юнит-тесты порядка списания: кошелёк хватает, не хватает, пуст, истёк, исчерпан недельный лимит, модель не из `models`.
- Возврат разницы: в кошелёк до истечения, сгорает после истечения, никогда не уходит в основной баланс.
- Конкурентные резервы одного аккаунта не уводят кошелёк в минус. Блокировка строки, как сейчас у `AccountBudget`.
- Интеграционный тест в отдельной PostgreSQL (`scripts/test-billing.cjs`) с подменённым OpenRouter.

## Метрики

Ежедневно до 2026-12-31:

- расход бонуса (всего и по аккаунтам), доля аккаунтов с ненулевым расходом;
- шаги, стоимость шага, попадания в кэш, хост (`UsageLog.region` пока пишется только для теста);
- ответы с `finish_reason = length`. Сейчас они не попадают в журнал: такие запросы записаны как HTTP 200. Нужно добавить запись этого поля.

## Открытые вопросы

1. **Тариф с 2026-01-01.** Сколько стоит и что включает. Предложение от 2026-11-19: $20 в месяц, внутри DeepSeek с недельным лимитом и небольшой пакет премиум-моделей. Решить до середины декабря, чтобы предупредить пользователей до сгорания бонуса.
2. **Участники курса без платного бюджета.** Получают ли они бонус? Если да, им нужен `AccountBudget` с нулевым основным балансом. Сейчас наличие `AccountBudget` переключает аккаунт на денежный учёт: см. `internal-access-and-billing.md`.
3. **Наличие `AccountBudget` как признак платного аккаунта.** У внутренних и тестовых аккаунтов он тоже есть. Перед массовым начислением нужно исключить внутренние аккаунты или решить, что они тоже получают бонус.
4. **Резервный маршрут.** Когда Wafer и другие дешёвые хосты недоступны, нужен ли прямой DeepSeek API. По ценам на 2026-11-19 ($0,15–0,30 за вход без кэша) это в 4–8 раз дороже Wafer.
