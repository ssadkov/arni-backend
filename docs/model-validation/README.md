# Поэтапное включение платных моделей чата

Первая модель для проверки — **Qwen3 Coder Next, Amazon Bedrock**, `qwen.qwen3-coder-next`, регион `us-east-1`. Следующие кандидаты: Qwen3 Next для дешёвых текстовых задач; Qwen3 VL для скриншотов; Kimi — отдельный сравнительный прогон. Sonnet не используется как автоматическая платная замена.

## Серверный список допуска

`ARNI_PAID_MODEL_ALLOWLIST` — JSON-массив точных ID. Фильтр действует и в `/api/models`, и в `/api/chat/completions`; подстановка скрытого ID вручную не обходит его. Проверка происходит до резерва денег и обращения к модели. Права Bedrock конкретного пользователя остаются отдельным необходимым условием.

- Не задан или пустая строка: совместимость с текущим внутренним каталогом. **Это не режим публичного выпуска.**
- `[]`: платные модели чата выключены; проверенные бесплатные модели остаются доступны.
- `["qwen.qwen3-coder-next"]`: включена только эта платная модель; одноимённый OpenRouter ID не разрешается.
- Некорректный JSON/ID: закрытый отказ для платных моделей, без обращения к провайдеру.

Устанавливать значение с Qwen в обычном окружении только после живого прохода приёмки. До него тестировать на отдельном deployment; для публичного выпуска обязательно задать список явно. Переменную менять через Vercel для нужного окружения, затем публиковать проверенную сборку backend. Без публикации изменение исходников не меняет работающий сервис.

При добавлении следующей модели расширять список на один ID после сохранения отчёта. Не объявлять модель проверенной по наличию в каталоге AWS. Доступ аккаунта, runtime IAM/ключ, доступ в Arni, маршрут, цена и пригодность для сценария проверяются отдельно.

## Что проверять перед включением

1. Карточка AWS: ID, регион, контекст, предел ответа, tools, изображения, тариф. У Qwen3 Coder Next контекст 262144 и нативный ответ до 16384; приложение сейчас ограничивает ответ своим отдельным пределом. Модель текстовая.
2. Реальный AWS доступ и инструменты: вызов → результат инструмента → законченный ответ.
3. Новый чат: тот же ограниченный обзор репозитория лендинга; ссылки на реально прочитанные файлы; без записи в проект.
4. Небольшая правка отдельного тестового проекта и исполняемые проверки результата. Не запускать произвольные shell-команды модели без контроля.
5. Длинный контекст, сжатие и продолжение после остановки. Сохранять пары tool-call/tool-result. Локальные регрессии не заменяют живой тест клиента.
6. Все вызовы задачи: выбранный/фактический ID, источник, регион, время, usage, кеш, ставки и стоимость. Отдельно показывать реальное списание и консервативный резерв/неизвестный исход.
7. Повтор по маршруту desktop → Arni backend → AWS. Прямой SDK-тест не подтверждает runtime-права backend или готовность Windows/macOS приложения.

## Контекст и деньги

- HTTP размер ограничен отдельно: 3,8 МБ. Сериализованные схемы инструментов тоже занимают место.
- Размеры в UTF-8 байтах не сравниваются с окном токенов и не выдаются за точный токенизатор.
- Для OpenRouter используется полученный контекст модели/провайдера (меньший из опубликованных), а не запасные 32K от таблицы Bedrock; отсутствие метаданных даёт явный отказ.
- При наличии CountTokens проверяется `input + maxOutput <= context`. В существующем пути CountTokens применяется к изображениям Anthropic в Bedrock.
- У Qwen3 Coder Next CountTokens не поддерживается: реальный контекст проверяет AWS. Локальная байтовая оценка используется только для консервативного резерва, ограниченного размером контекста; она может быть выше реальных расходов. Нативный предел ответа учитывается отдельно. Не обещать клиенту точный счётчик Qwen по этой оценке.
- Резерв денег не является списанием по фактическому usage. При подтверждённом отклонении контекста резерв возвращается; при неизвестном исходе сохраняется консервативный учёт.
- В `llm_preflight` записываются только request ID, модель/источник, числовые размеры, пределы и резерв. Тексты, аргументы инструментов, содержимое файлов и ключи не добавляются в эти диагностические записи.
- Контекстный отказ провайдера нормализуется в HTTP 400 / `context_too_large`; backend не повторяет его и не выбирает другую платную модель. Политика повторов desktop SDK проверяется отдельно.

Для Qwen Coder Next тариф Standard US: $0.50 / $1.20 за 1 млн входных/выходных токенов. Суммарные 100000 входных и 5000 выходных за все шаги = $0.056. В этом расчёте нет неподтверждённой скидки за кеш. Не считать одни и те же входные данные один раз, если они повторно передаются в каждом вызове.

Источники: [карточка Qwen3 Coder Next](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-qwen-qwen3-coder-next.html), [тарифы AWS](https://aws.amazon.com/bedrock/pricing/). Срез проверен 22 октября 2026; цены и доступ нужно обновлять перед новым прогоном.

## Воспроизводимые проверки

- `node scripts/test-request-limits.cjs` — offline, без базы и оплачиваемых вызовов.
- `powershell -NoProfile -File scripts/test-billing.ps1` — отдельная временная PostgreSQL, модели замоканы. Рабочая база не используется.
- `node scripts/validate-qwen-coder.cjs --run-billed --profile arni-bedrock-audit --repo C:/work/sadkov.info` — явный платный SDK-прогон с потолком $0.50, ограниченными инструментами только чтения и без автоматических повторов. Сначала проверяет вход и доступ AWS. Архивирует ответы и usage в игнорируемом `scripts/.cache/`; не публиковать эти файлы. По умолчанию итог даже успешного SDK-прогона — частичная проверка, а не разрешение публичного выпуска.
