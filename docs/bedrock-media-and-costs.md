# Скриншоты, изображения и учёт расходов ArniCode

Реализация подготовлена локально. Миграция production, активация соглашения AWS и публикация редактора — отдельные шаги запуска.

## Что сохраняется

`ModelRequest` сохраняет попытки: ID запроса, запрошенную и фактически вызванную модель, провайдера, регион, операцию, HTTP-статус, длительность до ответа провайдера и компактную ошибку. Несколько попыток маршрутизации могут иметь один ID запроса.

`UsageLog` сохраняет входные/выходные токены, модель, снимок цен за миллион токенов, стоимость в микродолларах (1 USD = 1 000 000), количество изображений и ID запроса. Для генерации отдельно сохраняются цена за картинку и `operation=image`. Для чата `imageCount` означает число входных скриншотов. Тексты запросов и входные скриншоты не сохраняются.

`costBasis=provider` — денежная стоимость от OpenRouter; `catalog` — расчёт по usage и сохранённым тарифам; `reservation` — консервативная оценка, если usage/результат потерян. `accounting=legacy` означает прежнее списание токенов с tokenBalance, а `reported/estimated` — расчёт бюджетного аккаунта. Эти признаки не подменяют друг друга.

Исторические записи без цены остаются без цены. Расчёт Bedrock по тарифу не является сверкой с итоговым счётом AWS: скидки, налоги и другие виды расходов надо сравнивать отдельно. Применение другой цены к тем же токенам даёт сценарную оценку: у другой модели токенизация и объём ответа могут отличаться. Проверка качества требует отдельных прогонов одинаковых задач.

В `/admin` отображается сумма записанных расходов, число записей без цены и ссылка на CSV за 30 дней. Экспорт: `/api/admin/usage/export?from=2026-10-01&to=2026-11-01`; нужна существующая админская Basic-авторизация. Максимум 10 000 строк, при превышении уменьшите период. Запросы с отказом смотрите в `ModelRequest`, неопределённые списания — в `BudgetReservation`.

## Лендинги и скриншоты

Managed Bedrock-каталог объявляет vision для поддерживаемых Claude. Вложения PNG/JPEG и изображения из результатов инструментов передаются в Converse, включая результат `screenshot_page`. До платного запроса с изображениями вызывается бесплатный `CountTokens` с foundation ID модели (без `us.`/`eu.`/`global.`); для текущих Sonnet 4.5 и Sonnet 4.6 этот вызов проверен через AWS API на синтетическом тексте. Если подсчёт не доступен, запрос останавливается до платного inference.

Нужны `bedrock:CountTokens` на foundation ID выбранного Claude и прежние права на вызов модели. Для Sonnet 4.5 дополнительно проверен реальный бесплатный CountTokens с синтетическим PNG 64×64. Другие новые модели могут требовать другой endpoint подсчёта; автоматического обхода проверки бюджета нет.

Ограничения: только встроенные `data:image/png|jpeg;base64,...`, до 20 изображений, суммарно до 2,5 МБ, стороны до 8000 px, JSON запроса до 3,8 МБ. Сервер не скачивает произвольные URL. Managed OpenRouter остаётся текстовым до отдельного внедрения надёжного мультимодального тарифицирования.

Пример задания агенту: «Сверстай лендинг по референсу. Запусти dev-сервер, открой страницу встроенным браузером, проверь скриншоты desktop и mobile, исправь визуальные расхождения». В ArniCode уже есть browser-инструменты `open_browser_page`, `screenshot_page`; включите их в настройках инструментов агента и разрешите доступ к нужной вкладке. Генерация картинки не заменяет проверку скриншота готовой страницы.

## Генерация PNG

Native Copilot Agent получает инструмент `arni_generate_image` / `#generateImage`. Он использует текущий вход ArniCode, генерирует одну PNG, сохраняет в единственный открытый локальный проект и открывает preview. Пример: «Создай hero-иллюстрацию в `public/generated/hero.png`, используй её на лендинге, затем проверь страницу по скриншоту».

Первая модель: `stability.stable-image-core-v1:1`, `us-west-2`, $0,04 за изображение. Цена проверена по AWS offer 14 октября 2026; при смене тарифа обновить серверную константу и клиентское описание вместе. Разрешены пропорции 16:9, 1:1, 21:9, 2:3, 3:2, 4:5, 5:4, 9:16, 9:21. Нет редактирования исходных изображений или генерации видео в этой реализации.

API:

- `GET /api/images/generations` — конфигурация и доступность для авторизованного аккаунта.
- `POST /api/images/generations`, Bearer JWT ArniCode, заголовок `Idempotency-Key`, JSON `{ "prompt": "...", "aspect_ratio": "16:9", "n": 1 }` — генерация, ответ с ID и приватным URL.
- `GET /api/images/{id}`, Bearer JWT владельца — получение PNG. Чужие файлы возвращают 404, кеш запрещён.

Ключ инструмента зависит от проекта, описания, пути и пропорций. При потере HTTP-ответа повтор с теми же значениями возвращает прежний результат. Изменённый payload с прежним ключом возвращает 409. Уже существующие файлы не перезаписываются; пути за пределами проекта и junction наружу отклоняются до генерации. После отправки запроса отмена чата не прерывает сохранение оплаченного результата.

Генерация требует `AccountBudget` и резервирует $0,04 с проверкой баланса, срока и окон. Подтверждённый upstream 4xx (кроме 408) возвращает резерв; таймаут, неизвестный исход или фильтрация сохраняют оценку. SDK не повторяет InvokeModel автоматически. При аварии процесса pending-запрос требует сверки администратором; повтор не отправляется в AWS. Существующий инструмент reconciliation может закрыть старый резерв консервативно; он не повторяет генерацию.

Готовые PNG хранятся приватно в `MediaGeneration.image` в PostgreSQL для восстановления и скачивания; удаляются каскадно при удалении аккаунта. Автоматического срока удаления в этой версии нет. Это вариант для небольшого числа пользователей; перенос бинарных результатов в S3 и политика хранения — следующий этап при росте.

## Что нужно сделать для запуска

1. В AWS Console открыть Amazon Bedrock → регион **US West (Oregon), us-west-2** → Model catalog → **Stable Image Core**. Проверить и принять предложенные условия доступа модели. Сейчас соглашение для этого аккаунта было `NOT_AVAILABLE`; наличие модели в каталоге само по себе не подтверждает возможность вызова.
2. Настроить `AWS_BEARER_TOKEN_BEDROCK_IMAGES` в защищённых переменных backend. Это отдельный ключ для `us-west-2`; основной `AWS_BEARER_TOKEN_BEDROCK` чата остаётся прежним. Региональные short-term ключи нельзя переносить между регионами. Не присылать ключи в чат и не коммитить их. В production предпочтительны временные IAM credentials; переход backend с bearer на IAM — отдельная задача.
3. Проверить права этого ключа на `bedrock:InvokeModel` для `arn:aws:bedrock:us-west-2::foundation-model/stability.stable-image-core-v1:1`. Права Marketplace для активации нужны администратору, а не runtime-ключу.
4. Применить исходную бюджетную миграцию, если её ещё нет, затем **один раз** `deploy/billing/20261014-media.sql`. Не применять миграцию автоматически к production при обычном тесте. Сгенерировать Prisma client и опубликовать backend.
5. Установить `ARNI_IMAGE_GENERATION_ENABLED=true`, выдать нужному пользователю бюджет API и опубликовать сборку ArniCode с новым инструментом. Первый реальный PNG будет платной проверкой интеграции ($0,04).
