## Кэш: фактическое поведение

`modelCapabilities().cache` настроен для Sonnet 4.6, Sonnet 4.5 и Haiku 4.5. `cacheConversePrefix` добавляет checkpoint в предпоследнее сообщение достаточно большой истории; последний динамический ввод остаётся после него. TTL не задан явно, используется стандартный 5-минутный режим. Qwen3 cache policy не задан: явные checkpoints для этих запросов не добавляются. Хранение готовых ответов с возвратом вместо inference не реализовано.

Счётчики AWS различаются: `inputTokens` не включает `cacheReadInputTokens` и `cacheWriteInputTokens`. В OpenAI-совместимом usage восстанавливается полный prompt count; при списании обычный input, cached read и cached write оплачиваются отдельными группами без двойного начисления. Для текущего 5-минутного Claude-кэша тарифные множители read=0,1 и write=1,25. Резерв учитывает повышенную цену записи. Снимок rates сохраняется в резерве и журнале, последующее изменение каталога не переписывает прошлую стоимость.

Попадание не гарантируется: нужны подходящий размер и совпадающий префикс в пределах TTL. Первый запрос может только создать кэш, после долгого рендера кэш может истечь. Кэш ответов, часовой Claude TTL и экономия от явного Qwen caching не входят в выпуск. [AWS prompt caching](https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-caching.html).

## Журнал и сравнение тестов

Клиент отправляет `X-Arni-Chat-Id` из sessionId; backend сохраняет его со списанием. Модель, регион, операция, попытки и ошибки находятся также в `ModelRequest`. История без chatId доступна в суммах аккаунта, а не в достоверной ретроспективной разбивке по чатам. Изображения сейчас смотреть в общей истории аккаунта. `reported` и `estimated` различать; расчёт по usage/каталогу не равен сверке со счётом AWS.

Для нового сравнения: отдельный чат на каждый прогон, одинаковые исходники/отрезок/разрешение/критерии качества, отдельные output-файлы; замерить время локального процесса и USD журнала независимо. Общий израсходованный бюджет аккаунта нельзя приписывать одному ролику. Тексты запросов и входные изображения в billing ledger не сохраняются.

## Проверки и ограничения

13 Bedrock/feed, 17 disposable-PostgreSQL billing и 9 media проверок прошли. Реальные AWS audit вызовы подтвердили tools всех семи Qwen, vision VL и Claude cache-write/cache-read. Платный production-запрос из приложения и качество видео остаются отдельными проверками. Журнал запросов и успешный CLI/каталог не доказывают успешный рендер.

Feed проверен на опубликованной 1.0.1: старая версия получает ZIP нужной архитектуры с хешем/размером; текущая и более новая — 204. DarwinUpdateService использует Electron releaseNotes как pending commit, поэтому `notes` содержит commit, а описание релиза отдаётся в `releaseNotes`. Ручное скачивание может запросить уже найденный commit при старой running version: блокировать такой запрос только по равенству commit нельзя. RU proxy иногда отвечал с таймаутом; повтор проходил, прямой Vercel отвечал быстро. Реальный GUI update на Mac не проверялся.

Не повторять production-миграцию без проверки схемы. Не извлекать все production secrets ради smoke-теста: использовать текущий вход приложения или узко разрешённый способ. Параметры доступа, balances, цены, региональные разрешения и срок сертификата — изменяемое состояние; перед следующим выпуском проверять заново.
